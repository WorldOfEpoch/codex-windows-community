# Security and privacy

This repository contains documentation and issue forms. It does not request credentials, connect to model providers, change a computer's settings, or install maintenance services.

Public issues are for sanitized symptoms, synthetic reproductions, and reviewed fixes. Do not publish secrets, private conversations, raw logs, full configuration files, application databases, or exploit details that could put other users at risk.

For a vulnerability in this repository, use GitHub's private “Report a vulnerability” feature when it is available under the Security tab. If the private option is unavailable, do not put sensitive details in a public issue; first request a private reporting channel without describing the exploit or disclosing data. For a vulnerability in Codex or another vendor product, use that vendor's official private disclosure channel.

If a public contribution accidentally includes sensitive material, stop sharing it and notify the maintainer through an available private channel. Remove the exposed attachment and address affected credentials through their owner. Deleting a visible file or comment does not guarantee that copies or repository history disappear.

Proposed fixes must identify their owner, scope, validation, and rollback. Do not use broad cleanup, privilege changes, firewall exceptions, credential copying, or mass process termination as an undocumented remedy.
